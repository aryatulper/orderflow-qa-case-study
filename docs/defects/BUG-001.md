# BUG-001 — Sign-in form remained visible after successful login

**Type:** genuine defect observed during this project's local visual QA pass on 2026-09-21

**Severity:** Medium · **Priority:** P1 · **Status:** Fixed locally; regression test added

**Environment:** macOS, Chromium, local OrderFlow API with PostgreSQL 17

## Preconditions

Open `/` with a fresh browser session. Use the seeded customer account `arya@example.test` / `demo123`.

## Steps to reproduce on the pre-fix build

1. Open the storefront.
2. Submit the valid login form.
3. Observe the page after the success message and catalog appear.

**Expected:** the sign-in panel disappears when the authenticated workspace appears.

**Actual observed:** the sign-in panel remained visibly rendered above the product catalog even though the header showed the signed-in customer. The HTML `hidden` attribute was set, but `.login-panel { display: grid; }` overrode the browser's default hidden styling.

## Resolution and evidence

Added a global `[hidden] { display: none !important; }` rule in `public/styles.css`. A Playwright `beforeEach` assertion now checks that the login panel is hidden and the workspace visible after sign-in. The failing visual state was observed manually; no pre-fix screenshot was retained, so this report does not claim one. The post-fix browser inspection and Playwright run both showed the corrected state.
